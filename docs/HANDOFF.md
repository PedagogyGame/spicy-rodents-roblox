## 3. Engineering rules learned (apply everywhere)
1. **Requires.** Within a root use relative string requires ("./X", "../Y"). Across roots (server/client/worldgen → shared) use the root's `Import.luau`:
   `local Swept = Import.shared("Traffic/Swept") :: typeof(require("../../shared/Traffic/Swept"))`
   Value from the engine or Lune, type from disk. Verified: all 138 modules require in the engine (BootSmoke, CI v3).
2. **Golden tests that need bit-exactness** decode with `tests/lib/PreciseJson.luau`.
3. **Routes.** Take `sampleCount` from the harvest record; never recompute ceil(3L).
4. **AI bodies.** One anchored root plus Motor6D limbs, moved with `workspace:BulkMoveTo` on roots only. All-parts anchoring costs about 1.4 ms per 130 rigs.
5. **Engine checks.** `Players.MaxPlayers` in the file is overridden live by the place's serverSize. Several streaming/lighting properties are NotScriptable and are verified by the Lune place test, not in the engine.
6. **Audio.** There is no runtime synthesis in Roblox. Use library sounds plus Audio API effects; budget 40/50 uploads per month (B3). Keep the tally in `docs/AUDIO_BUDGET.md`.
7. **Luau Execution** runs no physics, has no players and auto-runs no scripts. Physics feel, camera and fps checks need the owner's Studio (critique SQ-1, FE-1).
8. **Commit and push at every task boundary.** The container is ephemeral.
9. **Art lanes.** FBX export: axis_forward=Z, axis_up=Y, FBX_SCALE_ALL (1 Blender unit = 1 stud). Clips use convention spicy-clip/1 (Pose.CFrame = local joint delta in an axis-aligned joint frame) and export the cycle plus one closing key. Assets API displayName max 50 chars (enforced in upload_asset). SurfaceAppearance maps are not script-readable, so rigs load whole by asset ID; lune-baked kits use Box collision.
11. **No Git LFS.** lfs.github.com is unreachable from the container; binary art is committed as normal blobs (keep files small).
12. **Possession seams.** Keep Possession's Engine/BodyOps seams; on handoff call SweptCollision.markTeleported and MoveValidator.reset; brains implement { suspend(), resume(x, y, z) }.
13. **Tree meshes.** The 95 Blender trees are baked as MeshParts (Lune writes MeshId, InitialSize and TextureID into `build/Town.rbxm`; data in `data/art/tree_meshes.json` -> `generated/TreeArt`). They are visual only; invisible bark cylinders (role `Limb`) under them carry collision, raycasts and RouteCheck. No SurfaceAppearance is ever saved into the place (the Open Cloud publisher does not update them, D12; the place test enforces it): `Server/Assets/TreeArt` moves each uploaded model's SurfaceAppearance onto the baked parts after boot. Lune reads a written MeshId/TextureID back as `MeshContent`/`TextureContent`.
10. **BakeParity.** Compare plan hashes exactly, structure by hash, geometry with tolerance; never hash float32 sizes across Lune and the engine.

## 4a. Bowling (the first minigame; branch `feat/bowling-complete`, 2026-11-10)
- **Decision that needs the owner's yes:** the brief says "physics pins". Bowling does NOT use Roblox physics. The server decides every throw the moment the ball is let go, with pure seeded models (`src/shared/Minigames/Bowling/`: `BallPath` the ball's line, `PinModel` the pins, one `RollScript` table per throw), and every client plays that same table back. Why: Roblox physics is not the same on two machines and does not run in the cloud checks at all, so a physics pinfall could never be tested and could be scored differently from what a player saw. The pins still tip, slide, bounce off the kickbacks and fall into the pit. This is BUILD_PLAN D28's first pattern (the server owns every part) taken one step further; D28 carries a note. If the owner wants real physics pins instead, `BowlingLane` is the only place that would change.
- **What is where.**
  - Pure and Lune-tested (`src/shared/Minigames/Bowling/`): `BallPath`, `PinModel`, `RollScript`, `LaneCycle` (ready, rolling, counted, the pinsetter), `Referee` (whose sheet a throw goes on, when to re-rack, banner words, the end summary, the three computer players), `Intruders` (the squirrel rule), `AimModel` (the bowler's aiming and every word on screen), `Shots` (the camera). `PartPose` is the one piece of CFrame arithmetic the server and the client share.
  - Server glue: `Server/Minigames/BowlingLane` (writes the lane cycle's poses onto the baked parts; while a throw is in flight it moves only the ball, and writes the pins once when the throw is counted, so a many-part pin never arrives torn on a client that is drawing the same throw), `MinigameService` (announces a throw to everyone as `Minigame.State` kind `roll`; kind `rack` when a throw is cut short).
  - Client glue: `Client/Minigames/BowlingPlayback` (draws the script every frame), `BowlingClient` (wiring), `MinigameUI` (turn clock, hook pips, end card), `MinigameSounds` (silent placeholders with cue points).
- **The squirrel rule.** A squirrel or the Spicy Rodent on a lane cannot break a game: the pin model never sees it, so the throw always counts and a release is never held up. If the ball's path (or the pinsetter's sweep bar) reaches it, it is knocked into the gutter; the bowlers read "A squirrel ran onto the lane: the ball knocked it into the gutter. The throw counts." and the animal's player reads "A bowling ball knocked you off the lane!". People cannot get onto the lanes (the bake's LaneGuard).
- **Tests.** `lune run tests/run.luau bowling minigame attractions`. The glue is tested in Lune on a fake engine (`tests/lib/FakeEngine.luau`, cases in `tests/isolated/`, each run in its own process by `tests/lib/Isolated.luau`): the server service with real lane hardware, the client's playback against the server's poses, the bowler's controller through a turn, and the whole client through a game. `tests/engine/Minigames.luau` was rewritten for real throws but has NOT been run in the cloud from this branch (it needs someone allowed to run it). `tools/cloud/tasks/bowling_flow.luau` (runs `tests/engine/BowlingFlow.luau`) is the flow check with no clients: it reports every sheet's ten frame scores for twelve strikes (300), a mixed game (167), all spares (150) and a game of real throws, and that each session ends cleanly. It has NOT been run in the cloud either; the same flow passes in Lune on the fake engine (`lune run tests/run.luau minigames_service`).
- **On the main line (2026-11-11, branch `integ/bowling`).** Merged onto the main line with four review findings fixed, each with a spec: a slow throw is no longer refused by the clients (the check's limit is `PinModel.MAX_KEYS`), leaving the end card keeps every sheet under its own name, a newcomer at a lane showing its end card lets the players on that card go with words, and a seated bowler who triggers the prompt again gets no fresh rack. The main knobs are `PinModel.REACH` (carry), `BallPath.HOOK` and `HOOK_MAX_TURN`, `BallPath.NOISE_*` (the wildness outside the meter's green band) and `Referee.SKILLS`. The statistical specs pin today's behaviour: retune, then update their bands on purpose.

# S7: Headless animation (Blender clip -> Lune KeyframeSequence -> Open Cloud Animation)

**Question** (BUILD_PLAN §4.3 S7; D11). Can a clip go from bpy to a playable Roblox Animation with no
Studio step: Blender exports per-bone local CFrames per keyframe as JSON, Lune's `@lune/roblox`
builds a `KeyframeSequence` (Keyframes, Poses named after the RigSpec bones) and serialises it to
`.rbxm`, Open Cloud uploads it as an Animation, and `KeyframeSequenceProvider:GetKeyframeSequenceAsync`
reads it back in Luau Execution? Pass: the clip loads with the expected pose names (headless); in
OS-1a it plays without flipped joints (owner). Fallback: owner Animation Editor imports (D11, §6.6).

**Verdict: GO (headless half).** The clip uploaded in 2.1 s, was moderated `Approved` at once, and
loaded in Luau Execution in 181 ms with all 21 keyframes, the 14 expected pose names in tree order,
duration 0.667 s, `Loop`, `Movement` priority, both sync markers and the authored joint angle
(-0.600 rad on `FrontL_Upper` at keyframe 6). An `Animator` track on the same ID reports
`Length` 0.667 s and `Looped`. The "no flipped joints" half is visual and is queued for OS-1a with
a ready-made puppet (`assets/test/squirrel_puppet_s7.rbxm`). The owner's per-clip import fallback is
not needed unless OS-1a shows flipped joints.

## Method

1. `tools/blender/export_art.py` (bpy 5.2.3, 2 CPUs) rebuilds the S12 test squirrel
   (`squirrel_test_rig.build`, 13 bones, RigSpec names) and writes `build/art/squirrel_Run.clip.json`
   ("spicy-clip/1"): for each frame 1-20 of the Run action plus a loop-closing copy of frame 1 at
   frame 21, every bone's local delta from rest as a Roblox CFrame (12 numbers). The delta is
   `matrix_basis` conjugated into an axis-aligned joint frame at the bone head
   (`rest @ basis @ rest^T`), then into Roblox axes by the proper rotation
   M: Blender (x, y, z) -> Roblox (-x, z, y), so Blender's -Y front becomes `LookVector` -Z (D21).
   Bones also carry `head`, `tail`, `parent` and `restRotation` (Roblox axes). Two markers ride
   along: `Commit` at 0 s and `Recover` at 0.333 s (value `stride`). The same run also writes the rig
   FBX with the action (`build/art/squirrel_Run.fbx`, 185 KB), which D11 keeps as the import fallback.
   Whole export: 2.3 s wall.
2. `lune run tools/anim/build_clip.luau build/art/squirrel_Run.clip.json assets/test/squirrel_Run_s7.rbxm`
   (`tools/anim/KeyframeBuilder.luau`): `KeyframeSequence` > `Keyframe` (Time) > `Pose RootPart`
   (identity) > `Pose Root` > `Pose Hips` > ... nested like the bone tree, Linear easing, weight 1
   (0 for a bone with no pose in that keyframe), `KeyframeMarker`s on the keyframe with the same time.
   It validates the clip first and lists every problem. 3,591 bytes. Rebuilding from a fresh
   Blender export gives a **byte-identical** file (deterministic).
3. `node tools/cloud/cloud.mjs upload_asset assets/test/squirrel_Run_s7.rbxm --type Animation ...`
4. One Luau Execution task, `tools/cloud/tasks/art_probe.luau` on CI place version 3 (and again on
   version 4 with the same S7 result): `GetKeyframeSequenceAsync("rbxassetid://92005834447457")`,
   walk the first keyframe's Pose tree, collect markers, read one pose; then an
   `AnimationController`/`Animator` on a bare model loads the same ID as a track.
5. Unit tests: `tests/unit/anim_keyframes.spec.luau` (5 cases: tree shape, `.rbxm` round trip of
   CFrame/weight/easing, markers, invalid clips refused with all 6 seeded problems, the committed clip
   poses only RigSpec squirrel bones).

## OS-1a check (owner, about 2 minutes, in the existing OS-1a session)

In Studio (any place, e.g. a blank Baseplate): in the **Explorer**, right-click **Workspace** ->
**Insert from File...** -> pick `assets/test/squirrel_puppet_s7.rbxm` from the repo. Press **Play**. The Output prints "S7 puppet playing ... length 0.666". Look for: the tail waves up and
down, the four legs swing fore and aft along the puppet's long axis (left legs are red), the spine
rocks; nothing swings sideways or spins. The puppet is built by `tools/anim/build_puppet.luau` from the
same clip JSON: one block per bone, Motor6Ds named after the RigSpec bones, joint frames at the bone
heads with identity rotation (the clip convention), an `AnimationController` + `Animator`, and a
`Script` that loops the uploaded clip. (In `ReplicatedStorage.Assets.test` inside our builds the
Script is inert: legacy Scripts only run in Workspace or ServerScriptService.)

## Carry-forward for W1

1. **Clip convention "spicy-clip/1"** (documented in `tools/blender/export_art.py`): Pose.CFrame =
   local delta in an axis-aligned joint frame at the bone head, Roblox axes, studs. That equals
   `Motor6D.Transform` for puppets whose C0/C1 have identity rotation at the joint, which is how
   `build_puppet.luau` builds them; the W1 placeholder/procedural backend (`Actors/RigSpec` puppets)
   should build joints the same way so clips and procedural poses share one frame.
2. **Skinned rigs** (Lane 3, Art Inbox): Roblox `Bone` frames come from the FBX importer and may carry
   a rest rotation. Before the first skinned clip (W3), conjugate by the imported bone's rest
   rotation (`bones[i].restRotation` is exported for that), or export with bone axes aligned to
   the model; check once in OS-4 on the real squirrel. This is the remaining unknown behind
   "no flipped joints".
3. Pipeline per clip: `export_art.py`-style export -> `build_clip.luau` -> `upload_asset --type
   Animation` (about 2 s, `Approved` at once for this clip; record the moderation state in the
   manifest anyway, D12) -> one `art_probe`-style check per batch (about 0.2 s per clip inside one task).
   The 50-character name cap needs handling in `upload_asset` (truncate or shorten the prefix);
   `tools/cloud` is not in this spike's paths, so the lead should add the check.
4. `tools/anim/` is not in `tools/ci.sh`'s `LUAU_DIRS`: StyLua and Selene were run on it by hand
   (clean). Add it to `LUAU_DIRS` when `ci.sh` is next edited.
5. Loops: export the cycle plus one closing keyframe equal to the first (as here), so the track
   interpolates the last frame back into the first; `Length` is then cycle frames / fps.

# S8: Models and runtime art (headless parts a, c2, d)

**Question** (BUILD_PLAN §4.3 S8; D12, D13, D22; Addendum B1). Parts run here, headless: **(a)** a
textured rigid FBX through Open Cloud Model: what arrives through `InsertService:LoadAsset`, does a
Lune-written MeshPart with its MeshId/TextureID load and collide, and does the upload carry normal
and roughness maps? **(c2)** which appearance properties can a script write at runtime,
`SurfaceAppearance.Color` above all (the animal fur tint)? **(d)** can the key download a place
version for `rojo syncback`? Parts (b), (e) and the visual halves need the owner's Studio (OS-1b).
Pass: (a) renders with Box or Hull collision, maps recorded; (c2) the tint changes visibly per zone;
(d) recorded either way.

**Verdict: PARTIAL.** (a) **GO for the headless half** with a twist: the FBX upload arrives as a
`Model` > `MeshPart` > **`SurfaceAppearance`** (the PBR maps went into a SurfaceAppearance, not
`TextureID`), at the authored size, and `LoadAsset` at runtime keeps it; a Lune-written MeshPart
loads at the right size but always with **Box** collision and `MeshSize` 0. Whether the
SurfaceAppearance holds the normal and roughness maps cannot be read by any script (`Plugin`
capability) or downloaded (d), so "maps recorded" moves to OS-1b. (c2) **writes GO, visual pending**:
`SurfaceAppearance.Color` and `AlphaMode` (TintMask) are writable at runtime on a `LoadAsset`ed
SurfaceAppearance and on a new one, as are `MeshPart.Color` and `MeshPart.TextureID`; whether the
tint *shows* per zone is OS-1b. (d) **FALLBACK**: the asset-delivery API answers `403 "Scope not
authorized."` for the CI place version and for the model; the owner's GitHub "Upload files" route
(§4.3) stands unless the key gains that scope.

## Method

1. `tools/blender/export_art.py` builds a hollow-log blockout in an empty scene: a 32-segment bark
   tube with an inner bore and end annuli, 4.0 studs long, outer radius 0.8 (noise 5 %), bore 0.55,
   **1,152 triangles**, one material with three procedural 256 px PNGs (colour, normal, roughness)
   wired through a Principled BSDF, exported as FBX (`axis_forward="Z", axis_up="Y"`,
   `FBX_SCALE_ALL`, textures embedded): `build/art/hollow_log.fbx`, 56,492 bytes.
2. `upload_asset build/art/hollow_log.fbx --type Model`: 13.5 s including the operation poll,
   `Approved` immediately.
3. `tools/cloud/tasks/art_probe.luau` on CI place version 3: `LoadAsset`, list the tree, describe
   each MeshPart (MeshId, TextureID, Size, MeshSize, fidelities, children, SurfaceAppearance fields),
   pivot it to (1000, 500, 1000) and cast three rays at it (along the bore, down onto the top, across
   the side); `AssetService:CreateMeshPartAsync` on the same mesh with default options and with
   `CollisionFidelity = PreciseConvexDecomposition`, same rays; then the (c2) write probes (each write
   pcall'd and read back).
4. Lune-written MeshPart: `lune run tools/anim/s8_probe_place.luau build/test.rbxl build/art/s8_probe.rbxl
   114250471754267 89657770904034 1.658 1.647 4` adds `Workspace.S8Probe` with four MeshParts
   (requested fidelity Box, Hull, Default, PreciseConvexDecomposition; MeshId from step 3, TextureID
   = the S1 test decal) to the CI payload; `save_place --place ci` -> **version 4** (2.9 s); the same
   task on version 4 inspects them.
5. (d) `curl` through the proxy (key injected) to `asset-delivery-api/v1/assetId/{id}` and
   `.../assetId/118507593202954/version/3`, and `assets/v1/assets/118507593202954/versions/3`.

## Carry-forward for W1

1. **Lane 2 (cloud mesh) changes shape.** An FBX with a PBR material uploads as MeshPart +
   SurfaceAppearance. That is good for looks, but the saved place may not contain SurfaceAppearance
   (D12, invariant, `check_place`), and a Lune-written MeshPart gets Box collision and `MeshSize` 0.
   So: (i) **baked kits** (Lune-written into the place) are for Box-collision pieces and take their
   colour from a separately uploaded Image on `TextureID` (writable, also at runtime) or a
   `MaterialVariant` (S8f); export those FBXs without image textures so no SurfaceAppearance is made;
   (ii) **kits needing real collision or PBR** (hollow trees, arches, interiors) load at runtime:
   `LoadAsset` (Default fidelity, SurfaceAppearance kept) or `CreateMeshPartAsync(meshContent,
   {CollisionFidelity = ...})` (fidelity chosen at creation; it cannot be changed afterwards at
   runtime). This is the plan's own fallback "(a) kits load at runtime", now the default for those
   kits; the plugin bake before a Studio publish stays as the route to put them in the place.
2. **ID harvest:** `MeshPart.MeshId` (MeshContent) is readable in Luau Execution, so one
   `LoadAsset` task per batch harvests mesh IDs headlessly; SurfaceAppearance map IDs are **not**
   readable by any script, so Lane-3 rigs must keep being loaded whole by asset ID (D12 already does).
   `harvest_ids` should read MeshIds and asset IDs only.
3. **Fur tint (D13/D22):** runtime `SurfaceAppearance.Color` writes work server-side on a loaded
   SurfaceAppearance and on one created at runtime; keep the TintMask plan, pending the visual OS-1b
   check. The 6-8 pre-authored fur variants stay as the fallback only if OS-1b shows no visible tint.
4. **Scale and axes:** Blender `export_scene.fbx(axis_forward="Z", axis_up="Y",
   apply_scale_options="FBX_SCALE_ALL")` gives 1 BU = 1 stud and Blender -Y front = Roblox -Z
   (`LookVector`); use these settings for every Lane-2 export (D21).
5. **(d)** needs either the owner adding the asset-delivery (legacy asset) read permission to the API
   key, after which `GET asset-delivery-api/v1/assetId/{place}/version/{v}` should return a download
   location (untested), or the planned GitHub web upload per art batch.
6. Upload timings for budgeting: Model FBX 56 KB in 13.5 s (mesh processing), Animation 3.6 KB in
   2.1 s, place save 0.58 MB in 2.9 s; `LoadAsset` 0.27 s in a task.

# S5 / S19: AI scale (BrainScheduler, Perception, minimal brains, BulkMoveTo, Population)

**Question** (BUILD_PLAN §4.3 S5, re-scoped as S19; D4, D23). Can the server run the brief's standing
population as kinematic, anchored AI bodies inside the frame budget: AI <= 4 ms per 60 Hz frame on
average (<= 8 ms p99) as the regression baseline F-14, `BulkMoveTo` of 130-150 anchored rigs <= 1 ms,
memory recorded, the hard cap measured rather than assumed? Fallbacks: D4 (lower Mid/Far rates,
parallel perception, state stream for Mid/Far, non-Humanoid rigs for silent posts, cut the street,
shop and attraction floors; never the police and hospital floors).

**Verdict: GO** on every number, with one implementation rule for W1: **move anchored roots only and
let Motor6D-welded limbs follow** (0.17 ms for 130 rigs); moving every part through `BulkMoveTo`
(1,555 parts) costs 1.4 ms and misses the 1 ms line. AI cost is two orders of magnitude under the
budget (0.12 ms per frame average at 72 AI humans, 0.13 ms at 90), so the budget is not the limiting
factor for the hard cap; the limiting factors will be Humanoid replication and client rendering,
which Luau Execution cannot measure (W7 MicroProfiler, F-14).

## The synthetic worst case

`Scenario.build` (seeded mulberry32, so Lune and the engine run the same world): **72 AI human bodies**
(the task's S5 case: 24 townspeople + 6 shop workers + 14 hospital staff + 3 ambulance crew + 14 police
(6 beats, guard and car crew on station circuits) + 5 attraction staff + 6 reserve walking as
townspeople), **8 non-Humanoid riders** (cyclist-speed pedestrians), **14 squirrels** on the rails,
**1 AI spicy rodent**, **6 deer** (one fawn), **1 fox**, **45 vehicle proxies** (sedan boxes on the 14
v5.4 lanes at R(6.5, 9.5) u/s, 30 Hz), **2 fender benders** (two stopped cars each, two pedestrians and
an officer gathered) and **49 moving focus points** walking the sidewalk lanes as the players. The
second scenario forces every brain into the Near tier (the upper bound); the third rebuilds it with
**90 humans** (the S19 / D23 target). Puppets: R15-shaped 16-part humans with a Humanoid
(`EvaluateStateMachine = false`, states disabled), 8-part riders, 10-part squirrels, 9-part fox,
8-part deer, 5-part vehicles: 1,640 parts for 147 rigs (72-human case), 1,928 parts for 165 rigs.

So the plan's "<= 1 ms for 150 anchored rigs" holds only when the rig's root is the single anchored
part and the limbs hang off Motor6Ds: the assembly moves with the root at set time, with no physics
step needed (checked by reading a limb's position after the move: 0 error). Moving every part costs
about 0.9 us per part and misses the line at about 1,100 parts.

**Memory:** `Stats:GetTotalMemoryUsageMb()` 357 MB before, 364 MB after building 147 rigs, 360-371 MB
after the runs (the Luau Execution process baseline dominates); Luau heap 1.4 -> 2.3 MB after build,
3-4 MB during the run (`gcinfo`). `GetMemoryUsageMbForTag` returns 0 for Instances/BaseParts/Script in
this environment. Building 147 puppets with Humanoids took 34-39 ms.

**Lune cross-check** (same scenario, same seed): 0.048-0.063 ms per frame for the pure part, 725
ticks per s, identical tier split (60/41/1 with the Lune seed), liveness ok on seeds 1, 7, 42 for
1,800 frames; the engine's pure-Luau cost is 2-3x Lune's (instance-free), as expected for the shared
VM plus the puppet pose composition.

**Liveness** in all three engine scenarios: 0 stuck actors (every actor moved, vertical trunk running
counted), 0 NaN, 0 outside the world clamp.

## Regression baseline (F-14) to carry into `SimFull`

Record these in `build/reports/*.json` on every run and fail on a 3x regression:

- AI per frame (brains + motors + grid + traffic) at 72 humans, 49 spread foci: **0.12 ms avg, 0.18 ms p99** (gate 4 / 8 ms).
- AI per frame at 90 humans: **0.13 ms avg, 0.17 ms p99**.
- `BulkMoveTo`, roots only: **0.17 ms per 130 rigs, 0.24 ms per 165 rigs**; all-parts mode 1.4 ms per 1,555 parts (reference only).
- Brain ticks: about 730 per s with the 10/4/1 Hz tiers at 102 brains, 0 deferrals at the 4 ms budget.

## Findings for the lead

1. **Cross-root string requires do not work in the engine.** `require("../../shared/Config/Units")`
   from `ServerScriptService.Server.AI.Scenario` fails with `could not resolve child component
   "shared"` (the first AIScale task failed on it; `MoveValidator` uses the same form and will fail
   `BootSmoke` the same way). A probe task measured the alternatives: `../../../ReplicatedStorage/Shared/Config/Units`
   (walking up to the DataModel) **works**, `require(game:GetService("ReplicatedStorage").Shared.Config.Units)`
   works, `@shared/...` and `@ReplicatedStorage/...` aliases do not ("not a valid alias"), and absolute
   paths are refused. Lune needs `../../shared/...` instead, and the depth differs per root (client
   and WorldGen code is deeper in the DataModel than on disk), so no single string serves both. The
   spike's answer is `src/server/AI/Import.luau`: `Import.shared("Config/Units") :: typeof(require("../../shared/Config/Units"))`
   (value from the engine or Lune, type from the on-disk path). Decide once for every root (move the
   shim to `src/server/Import.luau` plus client and worldgen twins, or restructure the Rojo tree) and
   amend README "Requires".
2. **Anchored-root rigs with Motor6D limbs are the body mode** (§1.5): one anchored `RootPart`/
   `HumanoidRootPart`, every other part unanchored and welded; `BulkMoveTo` on the roots. This also
   matches how clips will animate (Motor6D transforms on the client, D3).
3. **The hard cap is not AI-bound.** 90 human bodies cost 0.13 ms of AI; D23's 90 stands until W7's
   live profile measures replication and rendering. The D4 fallbacks were not needed.
4. **Population:** `Population.plan()` validates against invariant 11 (police floor 9 incl. guard and
   crew >= 6, hospital 10, cap 90 - cap floors 33 = 57 >= 49 slots); the reserve pool runs to the
   hard cap (8 parked at boot, the rest built on demand) or the plan's "57 servable" arithmetic
   does not hold with 69 standing + 8 parked. `spikeS5()` (cap 72) is the measured case and fails
   only the 49-slot rule by design; the production numbers stay the plan's.
5. `Perception.spotted` matches all 3,010 golden vectors exactly (every intermediate); the port takes
   the target's height above local ground, so a squirrel on a hill is seen where v5.4's absolute-Y
   test would hide it (tested).
6. Brains tick perception inside their own LOD tick (10 Hz near), not at a separate 5-10 Hz; at
   these costs there is no reason to split them.

## What W1 should carry forward

- Keep `BrainScheduler`, `Perception` and the brain contract as they are; wire `Nav`, `Routes/*`
  (replace `SpikeRoutes` and the polyline `Kinematics.railPose` with `Curve`/`Motion`), `Data.lanes()`
  (replace `Pedestrian.defaultLanes()`), `World/Height` (replace the scenario's ground function) and
  `town/concealment.json` (replace `Perception.defaultConcealment()`).
- `ActorService`/`BodyFactory` build rigs as anchored root + Motor6D limbs and move roots only.
- `Puppets.luau` stays as the placeholder-body source for `tools/placeholders` and the `Actors`
  engine suite; the part names already follow `RigSpec`.
- `tests/engine/AIScale.luau` becomes the `SimFull` budget section; keep the three scenarios and the
  baseline above.
- Open: the Staff pace (1.4 u/s) and the officer beat shape are W0 tunables with no v5.4 source; the
  police station stand-in position (-300, 290) u must come from `data/town` in W1.
